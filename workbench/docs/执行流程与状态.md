# 说明书优先（2026-10-27）

默认 `Run.ps1 -InputModel` 以及 `Batch.ps1` 调用独立的 `workflow.py`。

1. 先按 SHA256 检查已核验成品索引、完整结果和本流程检查点。已完成的计划、图片、说明书、终结的分析直接复用。
2. 新输入严格导入。原有 STEP 按源顺序及子模型实例边界展开；无 STEP 时按层、y、x、实例 ID 自下而上排序，每步最多 `step_size` 件。这里只使用几何顺序，不调用静力或插入求解器。
3. 每件零件必须恰好覆盖一次；核对来源映射、BOM、连续步骤及非空步骤。明确的子组件装入步骤允许不取新零件。对原模型和步骤 MPD 展开后的零件、颜色、精确位置和变换逐件比较。不吸附或修复坐标。无法严格导入就保存诊断并停止该模型。
4. 生成步骤图、零件图、中文 PDF/HTML，检查逐步图片和 HTML 引用、PDF 可读性。立即输出“说明书已生成，稳定性待分析”及 PDF/HTML 路径；随后自动分析。
5. 一个受监督 Python 子进程执行最终模型和全部步骤的自重静力 LP。使用随附的 legolization 0.6.0；兼容层只调用该固定版本的 `_step_layout` 还原子组件前缀，没有修改 vendor 或 site-packages。没有重新调用智能规划/原认证函数。
6. 分析完成或超时后，复用原图，仅重新排入状态文字。PDF 更新先写临时文件再替换；若查看器锁定 PDF，则保留原文件并输出 `instructions_cn_status.pdf`。HTML、JSON 报告同步更新。说明书不会因未通过而撤回。

## 累计计时

`outputs/analysis_budget/<输入SHA256>/budget.json` 为模型共享预算，首次默认 1800 秒。计时从说明书路径打印完毕、启动分析子进程之前开始，包含导入、最终模型和所有步骤。启动下一次 LP 不重置时钟。单模型锁防止相同输出根中的重复任务。

父进程持有 deadline，LP 即使阻塞在原生库中，也会被父进程按本次创建的 PID（以及其子进程）停止；不枚举或终止其他模型、历史实验或无关 Python。已完成的最终模型及各步骤分别写原子 JSON。预算每秒保存，分析进度约每 20 秒输出。

通过、未通过、超时和异常均为终结状态，再运行同一输入不会自动重试或增加时限。不要删除/迁移预算来重新计时。父进程异常中断的记录会保守记为异常或超时，不重复启动；检查记录的 PID 后再人工处理。正常 Ctrl+C 会停止本次拥有的子进程并保存结果。

## 两类结果分别记录

| 字段 | 值 | 含义 |
|---|---|---|
| generation_status | PASSED | 覆盖、步骤图片、HTML 引用和 PDF 可读检查通过；合成/新模型的自动检查不代替逐页人工审阅 |
| stability_status | PENDING / 待分析 | 尚无完整静力结论 |
| stability_status | PASSED / 通过 | 本次最终模型、全部步骤自重静力和最终连通性检查通过 |
| stability_status | FAILED / 未通过 | 静力分析完整结束，存在不稳定步骤/最终模型或连通性风险 |
| stability_status | TIMEOUT / 超时未完成 | 总预算耗尽，部分结果保留；未检查的步骤仍未验证 |
| stability_status | ERROR / 求解异常 | 导入、求解器或进程异常；不能推断结构通过/未通过 |

本次独立分析范围为**自重静力**，不是按压插入或实物认证。保留已有插入风险；新计划不推定插入过程通过。报告记录实际求解器参数与地面假设；`ground=true` 只在分析布局中选择地面基准，不改交付 MPD。默认 `ground_pull=true` 的底板拉力假设与光滑桌面不同。目标值不是倒塌概率。StableLego/Gurobi 历史记录是另外的实验，未执行且不可混作本次结论。

历史兼容 API 和命令保留用于查阅及回归测试；`legacy-full/prepare/plan/source-plan/export-draft` 不属于新默认流程。日常仅使用 README 的默认单模型/批量命令，独立静力入口 `verify-steps` 也使用同一预算。
